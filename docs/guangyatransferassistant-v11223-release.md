# 光鸭转存助手 v1.12.23 验证记录

## 修复背景

MoviePilot 订阅《象行记 (2026)》时，原站实际没有该影片资源，但旧版日志显示 `影视卡片=25`、`原始资源=536`、`Magnet=20`。这些数字来自搜索页的模糊卡片及默认推荐内容，不是《象行记》的精确命中。`downurl成功` 也只表示详情接口请求成功。

## 修复内容

- 新版搜索页合法返回零条时直接认定为零结果；只有 `_obj.search` 无法解析、核心数组损坏或声明非零却没有有效卡片时才尝试 legacy 接口。
- 订阅自动检索先遍历全部搜索卡片，按当前订阅的精确标题、年份、电影/剧集类型筛选，再应用详情请求上限并调用 downurl。
- 主标题、纯标题及 TMDB 官方别名全部未命中时返回空候选，不再把首轮无关链接交给 Magnet/ED2K 规划。
- “我的资源检索”在全局数量截断前按当前订阅过滤迅雷、Magnet、ED2K，并分别显示“有精确候选”“未命中（来源正常）”“检索未完成”“来源异常”。候选仍需真实文件核验、入队回执和媒体库确认；升级时清除旧版持久化的假阳性搜索结果。
- 搜索缓存加入订阅 ID、TMDB ID、年份、季号和类型作用域；同一作用域的并发请求 single-flight，避免重复展开；已取得的精确详情快照由 Magnet 与迅雷共同使用。
- 日志分别记录接口健康、模糊卡片、当前媒体卡片、待核验详情链接、订阅候选、真实入队回执；不再把请求成功描述成影片有资源或已经入库。官方别名请求中途失败时明确标为“检索未完成”，不会写成确认无资源。

## 关键回归场景

- 合法零结果不请求 legacy，也不调用 downurl。
- 25 个无关卡片返回零候选、零详情请求；目标卡片位于第 26 位时仍只展开目标卡片。
- 电影订阅拒绝同名 TV/动漫卡片；`大象行记`、`象行记事` 不作为 `象行记` 命中。
- 数字本来就是片名的一部分时不会被误删；剧集的 `S02` 与 `第2季` 可按同一订阅身份匹配。
- 所有官方别名只返回无关链接时，上层收到零候选，同时保留 `success=True` 表示来源接口健康。
- 主查询正常但后续官方别名失败时返回 `search_complete=False`，明确表示无法确认零资源。
- 同页混合目标与无关链接时只上送目标链接。
- 外部 API 前 60 条均无关、目标位于其后时，目标仍会在截断前被保留。
- 同标题不同年份的订阅使用不同缓存；同一订阅并发检索只发出一次网络请求。
- 冷缓存统一检索完成一次详情展开后，迅雷复用该快照，不重复搜索或 downurl。
